Why WordPress Menus Break Your Design’s Navigation CSS (and How to Keep Your Own Markup)

Oct 29, 2026 Kerf Team 5 min read

The navigation is the first thing that breaks when a design moves into WordPress. You wrote .navbar .nav-link and a hover state for it; the imported page shows a plain bulleted list. The cause is the same almost every time.

What a Traditional Theme Does to Your Nav

WordPress themes normally print the menu with wp_nav_menu(), which writes its own markup: a ul with the class menu, and a li with the class menu-item for each entry. Your <nav> and your classes are gone, so every rule written for them has nothing to match:

Your design’s navAfter wp_nav_menu()
<nav class="navbar"><ul class="menu">
<a class="nav-link"><li class="menu-item"><a>
.nav-link { … } appliesthe rule matches nothing

The usual fixes are to rewrite the CSS for WordPress’s class names, or to write a custom menu walker that prints your markup. Both are work you did not have to do the first time.

How Kerf Keeps Your Navigation Intact

With Kerf, the navigation keeps its HTML tags, classes and attributes exactly as written. Only the destination of each link is bound to a WordPress page, by its ID or route. When the page renders, the markup is still your designer’s markup, class for class, so the stylesheet that styled it still does.

Editing the Menu Anyway

Keeping the markup does not mean freezing the menu. Select the header or the <nav> block in the editor and open the Menu panel in the sidebar. From there you can:

  • rename any item’s label;
  • point an item at any page, post or custom URL;
  • move items up or down, or remove them;
  • duplicate an item, which clones the designer’s own classes, so the new one looks like the others.

Links That Follow the Page

At import, Kerf matches the design’s internal links (about.html, /services) to your pages. External URLs, #anchor jumps, mailto: and tel: links are left alone. Under Kerf → Links you can see every internal link on the site:

  • a link whose page does not exist yet is flagged, and you can point it at an existing page or click Create page for a draft at that slug;
  • because the link is bound to the page, not to a typed address, it follows the page when you rename its slug, move it under a parent, or change the permalink structure;
  • removing a binding brings back the original href from the design.

Check It on Your Own Site

You do not have to take this on trust. Import a design, open the browser’s inspector on the imported page and compare the <nav> with the one in your ZIP’s index.html: the tags and classes are the same. The same idea, applied to the whole page and measured, is in how to test a conversion for drift.
